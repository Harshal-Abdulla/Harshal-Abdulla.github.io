Fault-tolerant notification system Personal · 2026
  • Distributed delivery pipeline built so a message is never silently lost and never sent twice, even when the broker, database or consumer crashes mid-flight.
  • Producer writes a PENDING row to Postgres before publishing to Kafka, so a crash between the two leaves a durable record that a recovery sweep picks up.
  • Consumer reads row status before acting (SELECT before UPDATE), which makes it idempotent by design and absorbs Kafka's at-least-once duplicates as a no-op.
  • Exponential backoff with a dead-letter queue, and retry counters held in Redis rather than process memory: process memory resets on restart so a poison message would loop forever, and parallel consumers would each keep a separate count.
  • End-to-end test drives all six behaviours against real Postgres, Kafka and Redis, including a message dead-lettering after its attempts are spent.

Stack: Python, Apache Kafka, PostgreSQL, Redis, Docker Compose  ·  github.com/Harshal-Abdulla/Kafka-Notification-System
